# M7 GitHub Actions CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 依追加設計 §2 建立 `.github/workflows/ci.yml`：推送到任何分支、以及開往 `main` 的 pull request 都會觸發；`web-api` job（ubuntu-latest、Node 24）依序跑 `npm ci` → `npm run typecheck` → `npm test` → `npm run test:workflow` → `npm run build -w @oc/web` → `npx playwright install --with-deps chromium` → `npm run e2e` → `docker build -f apps/api/Dockerfile .`；`desktop` job（windows-latest、Node 24）跑 `npm ci` → 建置 web 與 desktop → 明確下載 Electron 執行檔 → Electron 端對端測試，不打包安裝檔。e2e 失敗時上傳 Playwright 報告，保留 7 天。

**Architecture:** 只有一個工作流程檔，兩個互相獨立的 job。`feat/api` 只有 `apps/api` 與 `packages/*`；`feat/voice-notes-v1`（已合併 `feat/api`）有 `apps/web` 與 `apps/desktop`。所以需要 web 或 desktop 的步驟都用 `if: hashFiles('apps/<app>/package.json') != ''` 把關，缺少時改印一行 `::notice::` 說明略過。工作流程本身的結構由 `scripts/ci/workflow.test.mjs`（`node:test` + `yaml` 解析器）檢查，根 `package.json` 的單行 `workspaces` 由 `scripts/ci/root-package.test.mjs` 檢查；兩者都透過根 script `npm run test:workflow`（glob `scripts/ci/*.test.mjs`）在本機與 CI 執行。

**Tech Stack:** GitHub Actions（`actions/checkout@v5`、`actions/setup-node@v5`、`actions/upload-artifact@v4`）、Node 24 / npm 11、`node:test`、`yaml@^2.9.1`（eemeli/yaml，無相依套件）、Playwright 1.64、Electron 45、Docker（`node:24-slim`）。

## 設計決定

1. **缺少的 app 用 `hashFiles` 把關**：工作流程在每個分支都會跑。`feat/api` 上沒有 `apps/web`，`npm run build -w @oc/web` 會失敗（`npm error No workspaces found: --workspace=@oc/web`），`npx playwright install` 也找不到本地的 Playwright。因此 web 相關的三個步驟加上 `if: hashFiles('apps/web/package.json') != ''`；`desktop` job 的建置、Electron 下載與 e2e 加上 `if: hashFiles('apps/desktop/package.json') != ''`（有 desktop 一定也有 web，因為 desktop 直接讀 `apps/web/dist`）。缺少時各印一行 `::notice::`。`hashFiles` 不能用在 job 層級的 `if`，所以 `desktop` job 本身照常啟動，只略過步驟。
2. **`npm run test:workflow` 步驟**：放在 `npm test` 之後，只檢查 `scripts/ci/*.test.mjs`，幾百毫秒就跑完。用 `node:test` 而不是 Vitest：根目錄沒有 Vitest 設定，`scripts/ci` 也不是 workspace；根 `test` script 不必改，契約不動。`yaml` 只是 devDependency，不進 Docker 映像（Dockerfile 用 `--omit=dev`，而且只裝 `packages/shared` 與 `apps/api`）。glob 會一併執行 `root-package.test.mjs`，所以單行 `workspaces` 的檢查在 CI 裡也會跑。
3. **Electron e2e 用 `npx playwright test`（`working-directory: apps/desktop`）**：`npm run e2e -w @oc/desktop` 會再建置一次 web 和 desktop。設計把「建置」和「e2e」分成不同步驟，失敗時一眼就看得出是哪一段；`npx` 會往上找到根 `node_modules/.bin/playwright`。Electron 二進位由 `_electron` 直接啟動，不需要 `playwright install`。
4. **只在 e2e 本身失敗時上傳報告**：上傳步驟用 `if: failure() && steps.<id>.outcome == 'failure'`，避免 Docker 失敗時上傳一份通過的報告。web 上傳 `apps/web/playwright-report/` 與 `apps/web/test-results/`（web 設定有 html reporter 與 `trace: 'retain-on-failure'`）。desktop 依 `0d41665` 的決定上傳 `apps/desktop/playwright-report/` 與 `apps/desktop/test-results/`；兩者都 `retention-days: 7`、`if-no-files-found: ignore`。目前 desktop 的 `playwright.config.ts` 只有 `reporter: [['list']]`，不會產生 `playwright-report/`，所以那一行暫時只是無害的空路徑（`ignore` 不會讓步驟失敗）。保留它，是為了讓 desktop 加上 html reporter 後不必再改 CI；在 `apps/desktop/playwright.config.ts` 加 `['html', { open: 'never' }]` 屬於 `apps/desktop` 的變更，不在 M7 範圍，列為後續事項（見 Task 4 Step 7）。
5. **Electron 下載**：Electron 45 的 npm 套件沒有 `install`／`postinstall` script（只有 bin `electron`、`install-electron`），所以 `npm ci` **不會**下載執行檔；第一次 `require('electron')` 才下載約 110 MB，會吃掉第一個 e2e 測試的 60 秒逾時。因此 `desktop` job 在 `Build desktop` 與 `Electron e2e` 之間加 `Download Electron` 步驟，執行 `npm exec -w @oc/desktop -- install-electron`，同樣用 desktop 的 `hashFiles` 把關。`web-api` job 的 `env` 設 `ELECTRON_SKIP_BINARY_DOWNLOAD: '1'`；`desktop` job 與工作流程層級都不設。
6. **Actions 版本**：`actions/checkout@v5`、`actions/setup-node@v5`，`actions/upload-artifact@v4`。`setup-node` 用 `cache: npm`，快取鍵來自 `package-lock.json`。
7. **觸發與併發**（`2b22d48`、`0d41665`）：`push` 對所有分支（`branches: ['**']`）；`pull_request` 只限 `branches: [main]`，否則有開 PR 的分支每次推送會跑兩次（push ref 與 PR merge ref 落在不同的 concurrency 群組）。`concurrency.group` 是 `ci-${{ github.ref }}`，`cancel-in-progress` 是 `${{ github.ref != 'refs/heads/main' }}`：其他分支取消較舊的執行，`main` 上每個 commit 都保留結果。`permissions: contents: read`；每個 job `timeout-minutes: 30`。
8. **Docker 步驟一定執行**（`0d41665`）：`Build API Docker image` 加 `if: ${{ !cancelled() }}`，前面的步驟（例如 web e2e）失敗時仍會建置映像，Dockerfile 的問題不會被其他失敗遮住。映像只建置不推送、不加標籤。
9. **不在 CI 執行**：真實語音測試（`npm run e2e:real -w @oc/web`，需要金鑰）與 Android 建置（需要 JDK 和 SDK）。結構測試以不分大小寫的方式確認 `ci.yml` 沒有提到 `e2e:real`、`playwright.real`、`android`、`gradle`、`cap sync`、`secrets.`、`api_key`。
10. **根 `package.json` 的 `workspaces` 維持單行**：npm 加相依套件時會把它改寫成多行；整合分支、M1／M3a 的 grep 檢查都要求第 5 行是 `  "workspaces": ["packages/*", "apps/*"],`。`feat/api` 加入與 `feat/voice-notes-v1` 完全相同的 `scripts/ci/root-package.test.mjs`，並把 `package.json` 改成與整合分支逐字相同，之後合併不會衝突。

    .split(/\r?\n/)

    .filter((line) => line.includes('"workspaces"'));

});
